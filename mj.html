Configuration

Hébergement gratuit Firebase Spark, sans Cloud Functions. Les données sont séparées par groupe. Le MJ s'authentifie avec Firebase Authentication, les joueurs copient seulement une commande Roll20.

Accès et sécurité

Projet Firebase : —

UID MJ connecté : —

Copie cet UID dans la fonction isMJ() de tes règles Firestore, puis clique sur Publier dans la console Firebase. Aucune règle ne doit autoriser tous les utilisateurs à changer les prix. Voir GUIDE_CORRECTION_FIREBASE.md dans le ZIP.

Les règles Firestore doivent contenir le véritable UID MJ et doivent être publiées. Ne mets jamais de mot de passe dans les fichiers publics.

Après avoir changé des prix ou ajouté des objets, vérifie que le livre de prix des deux groupes est à jour. Les achats sont confirmés dans la boutique joueur V6, sans exécution directe de Roll20.

Tarification de l'atelier

Prix calculé sur les prix de base, les liaisons objet-affixe du catalogue RP validé et le nouveau barème de qualité Q. Les combinaisons de plusieurs affixes utilisent une addition de leurs suppléments : c'est une estimation dérivée, pas une valeur officielle fournie par le catalogue. Si un prix source manque, la publication est bloquée.

Rayons spéciaux : promotions et cabinet secret

Choisis un groupe ou les deux en haut, puis compose les listes. Les promotions utilisent les prix déjà définis dans le catalogue MJ : aucun rabais n’est inventé automatiquement.

Promotions

Marchandises secrètes

Le mot de passe peut être changé ici ; seul son empreinte SHA-256 est utilisée pour ouvrir le rayon. Pour un objet exclusivement secret, ne l’ajoute pas aussi aux promotions. La confidentialité réelle des fiches Firestore nécessite une gestion distincte des données publiques.
